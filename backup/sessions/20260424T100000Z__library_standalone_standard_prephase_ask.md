## Context (condensed from 4 rounds of Claude ↔ GPT review)

Astengine's root GPR declares `Library_Standalone => "encapsulated"`, which bundles the full Ada runtime into `libastengine.a`. When any consumer ALSO tries to be encapsulated (or composes with another encapsulated SAL), the final link produces ~1,400+ `multiple definition` errors on Ada runtime symbols. This is tracked as astengine issue #10. Astfmt deliberately uses `standard` to sidestep the problem, but the root-cause in astengine remains.

Investigation found two further facts:

1. **Template regeneration vector**: `hybrid_scripts_python/namespace_layers/namespace_layers.py:321-326` explicitly upgrades library-root GPRs from `standard` → `encapsulated`. Re-running this tool reintroduces the bug.
2. **Reference-project symmetry**: `hybrid_lib_ada` — the designated immutable reference architecture project — has the same `encapsulated` root GPR (originated from the same template). Whatever rule we add applies to it too.

**Architectural framing (locked unanimously by Claude + GPT):**

- `Library_Interface` is the architectural enforcement mechanism (public-API visibility).
- `Library_Standalone` is a build-model setting (runtime bundling), not an architectural boundary.
- Our Ada ecosystem is Ada-toolchain-aware everywhere (all consumers have GNAT + system RTS). No consumer legitimately needs `encapsulated`.
- The fix aligns GPR build configuration with the already-approved architecture — it is **not** an architecture change. No owner-escalation required.

## Scope of PR 1 (this slice)

PR 1's purpose is to land the **tooling** pieces so downstream repos can safely flip their root GPRs in PR 2a/2b without a regression vector.

### Primary changes

1. **`namespace_layers/namespace_layers.py`** — remove the `standard → encapsulated` auto-upgrade at line 321-326. Library-root GPRs generated by this template will retain `Library_Standalone use "standard";`. The `Library_Interface` customization in `_ns_library_interface()` stays.
2. **`arch_guard/adapters/ada.py`** — extend `validate_config()` to also scan the root GPR (`<project_root>/<project_name>.gpr`). Checks:
   - **Require** `for Library_Standalone use "standard";` — pattern match must find it.
   - **Reject** `for Library_Standalone use "encapsulated";` — pattern match must NOT find it.
   - **Require** `for Library_Interface use (...);` — pattern match must find it.
   - On any failure, emit the canonical error message (see below).
3. **Tests** (new `tests/` directory — option (a) locked):
   - `tests/test_arch_guard_root_gpr.py` — pytest cases:
     - positive: valid root GPR with `standard` + `Library_Interface` → passes
     - negative 1: root GPR with `encapsulated` → fails with canonical error
     - negative 2: root GPR missing `Library_Interface` → fails
     - negative 3: root GPR missing `Library_Standalone` entirely → fails
   - `tests/fixtures/valid_root_standard.gpr` — minimal valid root GPR
   - `tests/fixtures/invalid_root_encapsulated.gpr` — root GPR with `encapsulated`
4. **Repo hygiene**: adopt `backup/sessions/` convention (this file + README). Small, clearly separated from the technical fix.

### Out of scope (deliberately)

- **No** change to any consumer repo (astengine, hybrid_lib_ada, astfmt, etc.) — those ride in PR 2a/2b/3.
- **No** change to `arch_guard` validation of `src/application/application.gpr` — already correct.
- **No** change to the layer-dependency rules or source-file validators.
- **No** change to `Library_Interface` semantics or error text.
- **No** changes to `feat-compile-guides` branch work.
